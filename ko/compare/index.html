ecp와 codegraph, GitNexus 비교

세 가지 코드 그래프 도구, 같은 체크아웃, 같은 머신.

셋 다 저장소를 그래프로 만들어 구조적 질문에 답하지만 최적화 방향이 다릅니다. codegraph와 GitNexus는 그래프를 메모리나 SQLite에 두는 Node 서비스이고, ecp는 미리 만든 그래프를 mmap으로 읽는 무상태 Rust 바이너리입니다. 따라서 질의 한 번의 비용은 워밍업이 아니라 프로세스 시작 한 번입니다. 아래 수치는 이 프로젝트가 직접 측정한 값이며 측정 조건과 함께 공개합니다.

측정 조건

  • Versions — ecp 0.4.2 · codegraph 0.9.4 · gitnexus 1.6.5
  • Hardware — AMD Ryzen 9 9950X (16 logical), Linux
  • Same checkouts, same machine. All tools capped at a 1 MiB max-file-size threshold where configurable (gitnexus hard-codes 512 KB). ecp medians over 5–7 runs. ecp is a stateless one-shot CLI, so every latency includes full process startup — no daemon, no warm-up.

이 수치가 말해주지 않는 것

머신 한 대, 버전 한 조합, 코퍼스 두 개의 결과일 뿐입니다. 어떤 도구의 API가 내 용도에 맞는지, 언어 지원이 내 스택과 맞는지, 이 둘과 다른 모양의 저장소에서 어떻게 동작하는지는 답하지 않습니다. 콜드 인덱스에서 지는 도구라도 다른 둘이 답하지 못하는 질문에 답한다면 옳은 선택일 수 있습니다. 결정하기 전에 자신의 저장소에서 다시 실행해 보세요. 명령은 각 프로젝트 README에 있습니다.
