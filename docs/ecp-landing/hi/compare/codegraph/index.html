ecp vs codegraph vs GitNexus

तीन code-graph tools, समान checkouts, समान machine।

तीनों repository का graph बनाते हैं और उस पर structural सवालों के जवाब देते हैं। फ़र्क़ इसमें है कि हर एक किस चीज़ के लिए optimised है: codegraph और GitNexus Node services हैं जो graph को memory या SQLite में रखती हैं, जबकि ecp एक stateless Rust binary है जो prebuilt graph को memory-map करती है — यानी एक query की लागत warm-up नहीं, सिर्फ़ एक process start है। नीचे के आँकड़े project की अपनी measurements हैं, उन शर्तों के साथ published जिनमें वे निकले।

ये कैसे मापे गए

  • Versions — ecp 0.4.2 · codegraph 0.9.4 · gitnexus 1.6.5
  • Hardware — AMD Ryzen 9 9950X (16 logical), Linux
  • Same checkouts, same machine. All tools capped at a 1 MiB max-file-size threshold where configurable (gitnexus hard-codes 512 KB). ecp medians over 5–7 runs. ecp is a stateless one-shot CLI, so every latency includes full process startup — no daemon, no warm-up.

ये आँकड़े क्या नहीं बताते

ये एक machine, versions का एक set, दो corpora हैं। ये इस बारे में कुछ नहीं कहते कि कौन सा tool आपकी चाहत की API देता है, उसकी language coverage आपके stack से मेल खाती है या नहीं, या इन दोनों से अलग बनावट वाली repository पर वह कैसा बर्ताव करता है। Cold index में हारने वाला tool फिर भी सही चुनाव हो सकता है, अगर वह ऐसा सवाल हल करता है जो बाकी नहीं कर पाते। फ़ैसला करने से पहले इन्हें अपनी repository पर दोबारा चलाएं — commands हर project की README में हैं।

आँकड़े आख़िरी बार ecp 0.11.0 के लिए update हुए। कोई सुधार हो तो issue के रूप में ज़रूर भेजें।
