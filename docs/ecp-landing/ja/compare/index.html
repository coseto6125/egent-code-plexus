ecp と codegraph と GitNexus の比較

3 つのコードグラフツール、同じチェックアウト、同じマシン。

3 つともリポジトリをグラフ化して構造的な問いに答えますが、最適化の方向が異なります。codegraph と GitNexus はグラフをメモリや SQLite に保持する Node のサービスで、ecp は事前構築したグラフを mmap で読むステートレスな Rust バイナリです。つまり 1 回のクエリのコストはウォームアップではなくプロセス起動 1 回分です。以下の数値は本プロジェクト自身の計測で、測定条件を添えて公開しています。

測定条件

  • Versions — ecp 0.4.2 · codegraph 0.9.4 · gitnexus 1.6.5
  • Hardware — AMD Ryzen 9 9950X (16 logical), Linux
  • Same checkouts, same machine. All tools capped at a 1 MiB max-file-size threshold where configurable (gitnexus hard-codes 512 KB). ecp medians over 5–7 runs. ecp is a stateless one-shot CLI, so every latency includes full process startup — no daemon, no warm-up.

この数値が語らないこと

1 台のマシン、1 組のバージョン、2 つのコーパスの結果にすぎません。どのツールの API が自分の用途に合うか、言語カバレッジが自分のスタックに合うか、この 2 つとは形の異なるリポジトリでどう振る舞うかには答えていません。コールドインデックスで負けるツールでも、他が答えられない問いに答えられるなら適切な選択でありえます。決める前に自分のリポジトリで再実行してください。コマンドは各プロジェクトの README にあります。

数値は ecp 0.9.1 時点のものです。誤りがあれば issue でご指摘ください。
