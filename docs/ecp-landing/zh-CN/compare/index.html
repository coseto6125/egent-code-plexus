ecp 对比 codegraph 与 GitNexus

三个代码图谱工具，同一份 checkout，同一台机器。

三者都会把仓库建成图并回答结构性问题，差别在优化方向：codegraph 与 GitNexus 是 Node 服务，把图放在内存或 SQLite 里；ecp 是无状态的 Rust binary，用 mmap 读预先建好的图，所以一次查询的成本是一次进程启动而不是预热。下面的数字是本项目自己的实测，连同产生它们的条件一起公布。

测量条件

  • Versions — ecp 0.4.2 · codegraph 0.9.4 · gitnexus 1.6.5
  • Hardware — AMD Ryzen 9 9950X (16 logical), Linux
  • Same checkouts, same machine. All tools capped at a 1 MiB max-file-size threshold where configurable (gitnexus hard-codes 512 KB). ecp medians over 5–7 runs. ecp is a stateless one-shot CLI, so every latency includes full process startup — no daemon, no warm-up.

这些数字没有告诉你的事

它们来自一台机器、一组版本、两个 corpus。它们没有回答哪个工具的 API 更合你的用法、语言覆盖是否对得上你的技术栈，也没有回答在与这两份形状不同的仓库上会怎样。冷索引输掉的工具，如果它能回答其他两者答不出的问题，仍然可能是对的选择。决定之前请在你自己的仓库上重跑一次，命令在各项目的 README 里。

数字对应 ecp 0.9.1。有误请开 issue 指正。
