ecp 對比 codegraph 與 GitNexus

三個程式碼圖譜工具，同一份 checkout，同一台機器。

三者都會把 repo 建成圖並回答結構性問題，差別在最佳化的方向：codegraph 與 GitNexus 是 Node 服務，把圖放在記憶體或 SQLite 裡；ecp 是無狀態的 Rust binary，用 mmap 讀預先建好的圖，所以一次查詢的成本是一次行程啟動而不是暖機。下面的數字是本專案自己的實測，連同產生它們的條件一起公布。

測量條件

  • Versions — ecp 0.16.2 · codegraph 1.6.2 · gitnexus 1.6.12 (2026-10-22)
  • Hardware — AMD Ryzen 9 9950X, Linux (WSL2), pinned to 8 logical cores
  • Same checkouts, same machine, one tool at a time. All three capped at 1 MiB per file. Index medians over 3–5 runs, queries over 7; cold-index ratios from interleaved runs. ecp is a stateless one-shot CLI, so every latency includes full process startup — no daemon, no warm-up.

這些數字沒有告訴你的事

它們來自一台機器、一組版本、兩個 corpus。它們沒有回答哪個工具的 API 比較合你的用法、語言覆蓋是否對得上你的技術棧，也沒有回答在跟這兩份形狀不同的 repo 上會怎樣。冷索引輸掉的工具，如果它能回答其他兩者答不出的問題，仍然可能是對的選擇。決定之前請在你自己的 repo 上重跑一次，指令在各專案的 README 裡。
